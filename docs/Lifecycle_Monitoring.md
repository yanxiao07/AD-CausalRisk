# 同一快照的联合生命周期监测

`research_runtime.lifecycle_monitor.evaluate_lifecycle_monitor`接收两份十变量快照、同批次的两份结局/概率快照和预定义`LifecycleProtocol`。只接受调用者内存；不读取文件、不加载模型、不推理或拟合。该工程支撑FR-25和研究主线第1→3→4环节，不认证真实部署监测或个人因果效应。

`LifecycleProtocol(binning, performance, primary_model_version)`绑定既有参考分箱、24月性能协议和主模型。调用者先固定`protocol_digest(protocol)`，调用时传入`expected_protocol_sha256`。摘要固定声明，不证明声明真实或规则确实事先确定。每批特征与性能必须同数据版本、清单摘要、身份命名空间和人员集合，允许行序不同；模型、artifact、预测策略、特征契约/单位、锚点、终点及亚组规则均校验，参考协议须一致。共享ID必须保持同一锚定事件历史，不能偷偷更新随访或更换landmark。

统一门槛先连接双方批次成员、十特征缺失/固定箱、结局、所有模型概率箱和所有亚组资格。任一非空联合组少于5人，**整个报告SUPPRESSED**，两个计算器均不调用、两个子报告均为null，不输出人口计数或小组细节。两份单独安全的报告不能直接拼接：人工1/9/9/1交叉例中两边边际均为10人，合并后两格仅1人，必须抑制。此规则不构成差分隐私，也不认证跨自适应查询发布安全；调用者须控制既往发布组合。

通过后才复用原`evaluate_feature_drift`和`evaluate_performance_monitor`，不复制统计实现。入口复制数值、概率、成员并按ID排序，使后续调用者修改不影响已检查数据。输出包含计划/清单/模型/策略/规则绑定、操作调用/返回计数和两个原聚合报告；没有人员ID、原值、逐人概率、日期、成员列表或分箱切点。任一子计算失败不返回部分成功；原不可估特征或空亚组提升为`COMPLETE_WITH_LIMITATIONS`，保留原null和原因。空批不当作零漂移/零误差。

早截尾仍为未知，cause2仍是其他痴呆已知非AD；Brier/ECE和风险范围为有限样本可达补全界限，非置信区间，不声称跨指标/面板同时可达。不估计KM/IPCW、不作跨批性能差或临床效应。结果通过严格有限JSON序列化检查。参考计划与预测的真实性、历史可用性、OOF身份及亚组依据仍需独立核验；无自动告警、校准更新、部署或临床准入。

本地人工验收：在仓库根目录用含NumPy的既有研究解释器运行`research_runtime/tests/test_lifecycle_monitor.py`。测试覆盖合并反推、ID连接/行序、版本/规则拒绝、重叠事件历史、缺失/空/未知、复制隔离、错误不返回部分报告和有限JSON；不重做已关闭的统计真值矩阵。
