## 停止原因与方法纠正

审计脚本额外要求`model_state_identity(deepcopy(model)) == model_state_identity(model)`。这个跨对象要求强于原函数的“同一内存对象的前后诊断”，没有通用保证。

零拟合人工森林反例保留相同类别数值，但数组视图步长由16变为8，深拷贝前后`joblib.hash`不同；当前安装的joblib实现确实把数组步长纳入摘要。该反例说明原审计断言不适合作为通用数值等价判据，不代表已查明真实RF的具体内部布局变化。真实RF没有重读，实际触发字段仍未隔离。

后续内存变动挑战应先为每个待挑战副本固定它自身的摘要，再验证变动被发现，同时独立检查原对象不变；不能把副本规范化造成的摘要差直接解释成模型损坏。人工反例通过这一检查。生产状态函数本轮保持原样，未通过放宽生产校验或更改artifact摘要来求成功。
