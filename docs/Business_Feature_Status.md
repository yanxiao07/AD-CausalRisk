# 业务功能状态与边界

本页对应第1→2→3→4环节的工程支撑。验收对象是合成课程系统的授权、资料、任务、结果与页面；它不表示四环节科研或临床需求已经完成。

下表记录已验收的 Java 业务行为；涉及前端界面的描述为本地候选或接入目标。主分支页面接入情况见[前端 README](../frontend/README.md)，后端逐项证据见[后端验收](Backend_Requirements_Acceptance.md)。

接口以 [Java OpenAPI](../contracts/java-business.target.openapi.json) 的 **61 个操作**为准：59 个课程业务操作和 2 个表格研究任务操作。Java 路由覆盖测试对比实际路由集合。课程 Python 计算契约保持不变。

## 已实现的业务链路

| 审查项 | 当前行为与入口 |
| --- | --- |
| G01 写权限 | 复核/随访仅ADMIN或拥有原始资料授权的DOCTOR；PATIENT角色优先否决；RESEARCHER不因可读而可做临床写入 |
| G02 自动质量 | 每次检查独立持久化ID、规则、操作者、版本、摘要及覆盖信息；最近访视全缺失保持BLOCKED，人工批准不补造有效值 |
| G03 特征读取 | 档案详情返回真实特征；原始资料权限与患者摘要分开 |
| G04 输入追溯 | 访视、特征及导入推进版本；任务保存不可变的实际请求、来源记录绑定、SHA-256与质量检查ID。历史未捕获输入不从当前资料重建 |
| G05 审计 | 登录/失败、拒绝访问、资料写入、导入、质量、任务、复核、随访、授权和导出记录主体、结果与追踪号；管理页服务端分页过滤 |
| G06 任务状态 | 新提交入口返回PENDING任务号；后台原子转RUNNING，最终结果持久化；仅PENDING可取消。应用重启后遗留活动任务关闭为TASK_INTERRUPTED，不自动重算 |
| G07 档案录入 | 档案页建档、编辑、归档、访视/特征来源及缺失原因录入；原有批量评估入口保留 |
| G08 服务端筛选 | 档案关键词/状态/日期；评估档案/复核/演示等级/日期；任务档案/状态/日期。授权先于计数和分页 |
| G09 导入 | 列映射、原文件与映射保留、历史任务恢复、预检/确认入库和错误CSV下载；映射与原文共同绑定幂等身份 |
| G10 质量展示 | 自动PASS/WARN/BLOCKED报告与人工审核队列分开；CSV访视也触发人工QC；编号/别名搜索已接入 |
| G11 医生工作台 | 授权范围完整聚合、待复核、今日/逾期随访及待办入口 |
| G12 随访 | 跨受试者分页查询，今日/逾期/未来7日窗口，改期、事项、状态、负责人和备注；选人远程搜索；当前页CSV含真实行身份 |
| G13 终态保护 | CANCELLED/COMPLETED后不可通过省略status修改时间或事项；执行备注可继续补充 |
| G14 账号与范围 | 用户、角色、启停、密码、医生联系字段及档案授权/撤销。新研究账号默认ASSIGNED，仅已授权档案；管理员可显式授予ALL演示队列范围 |
| G15 报告 | 报告列表、授权HTML/PDF/JSON附件、研究/随访模板，带来源、版本、限制、输入绑定及复核身份/意见/时间；PDF内嵌OFL中文字体 |
| G16 图与解释 | 保留原生拖拽/缩放，支持解释路径选择高亮及PNG导出；贡献、正负、基准、截断、来源、缺失与限制均展示 |
| G17 演示语义 | 分数与等级标明演示排序；患者使用固定白名单说明，不转发任意内部限制或原始分数 |
| G18 管理统计 | 数据库对全部授权范围聚合；随访仅预览最多100条并明确标识，全部记录单独分页 |
| G19 配置 | Java/Python运行状态、版本、已安装模型新任务开关；个人字号/密度/成功提示偏好持久化并应用 |
| G20 患者 | 未来最近随访的事项/时间、过期数量及已配置医生联系方式；无配置明确显示未配置 |
| G21 历史入口 | 档案本人评估/任务历史、原始来源、质量覆盖及量表趋势；报告展示复核记录；图页面可比较同一档案历史结构 |
| G22 文档契约 | OpenAPI、模块说明与功能指南同步；新增前端构建/任务页CI定义。远端CI是否通过须以实际运行结果为准 |
| G23 原始超界值 | Python请求使用raw数值，30.004不能因展示舍入为30.00而成为合法输入；原始候选请求可用于审计但不声明满足算法准入 |

## 权限与兼容

- 按Design_Guide第1节，纯ADMIN仅下发audit/system/users三个业务菜单，分别对应审计、模型配置/系统状态、账号/角色；工作台由前端统一提供。研究/医生业务菜单仅由相应角色贡献，多角色仍按角色并集，PATIENT优先否决。管理员保留既有服务端管理权限，不以缩减菜单替代接口权限检查。
- ADMIN管理全体演示资料；患者混合角色仍按PATIENT否决。新用户不允许PATIENT与其他角色混用。
- 旧合成研究账号迁移后明确保留ALL策略；新研究账号默认ASSIGNED。VIEW可读原始资料并请求评估，MANAGE可编辑/录入/导入/审核质量；自建或自行导入的新档案获得MANAGE。
- 医生需要VIEW/MANAGE才能读原始评估和维护临床随访/复核；MANAGE才能编辑档案。患者仅绑定一个SUMMARY_READ档案，不能读取图、原始分数、输入快照或内部备注。
- 密码重置和停用会撤销现有会话；角色和数据范围、对象授权每次请求重新检查。界面隐藏不替代服务端校验。
- 原同步任务接口和报告JSON资源继续保留；新前端采用异步submit与附件download接口。
- 导入错误列表及其CSV沿用预检错误数量上限，行数统计保持完整；下载不代表无限错误明细。
- 自动质量报告是独立的资料检查，预测窗口等算法资格仍以Python实际BLOCKED/WARN结果为准，不把两者混成一个状态。

## 验证与未完成边界

Java `mvnw verify`覆盖真实Spring MVC/会话/迁移/H2权限与事务，新增26项业务回归及1项路由契约覆盖；算法客户端的模拟测试与真实合成Java→Python调用分开记录。Python课程733项回归保留。前端有构建、任务页乱序/错误回归及使用真实服务的 `scripts/e2e-business.mjs`。

迁移 V11 加入来源、质量、输入快照、偏好、模型配置等字段；V12 加入研究数据范围；V13 增加独立研究快照和任务表。当前为 H2 MySQL 兼容模式验证，**MySQL 8 实际迁移、备份恢复与部署待验收**。升级现有库前备份，不能删库或修改历史 Flyway 脚本规避校验。

本地任务队列与重启恢复按**单应用实例独占任务库**设计。跨实例部署须先增加任务租约/实例归属；当前不声称提供分布式队列或Python运行取消。Python阶段耗时只在实际完成后展示。

六个表格模型的参数、状态与训练参考已通过[数值组件核验](Model_Artifact_Admission.md)。真实宿主资格、监测双批输入及独立/临床证据仍开放；固定阴性图比较、不可估计及抑制结论保留。模型配置只管理已安装的合成课程模型，不能用页面开关替代科研准入。

## 本地研究材料定位与已接入展示

本地 `config/research_model_review.json` 已绑定七变量与多模态模型清单及封存聚合结果；受控主机的 `data/adni/processed/core_final_training_2026-10-24`、`core_multimodal_comparison_2026-10-24` 各有三项最终目标表格模型，`core_graph_comparison_2026-10-25` 有九项最终三臂/种子图模型。本轮只核文件存在性，未读取参数或重新执行这些研究。模型存在，不能以“没有模型”描述实际缺口。

新增 `/research/evidence` 页面，由Java授权提供15项候选模型的主机路径定位及十份已提交的研究说明/聚合表。原数值、分母、扰动范围、阴性/不可估和抑制状态保持；每份说明绑定实际打包字节SHA-256，源文件只维护于docs，不另抄一套结果。Java通过 `research.artifacts-root` 指定受控主机根目录；未配置时显示未配置核对，不能把它误判为模型不存在。接口仅进行固定白名单文件存在性核对和已提交文档读取，不反序列化模型、读取逐人输入或训练。

独立表格研究通道已完成[人工快照联调](../backend/README.md#本地研究任务联调)。FR-11/12 真实模型业务推理、FR-15/16 同次真实模型解释、FR-22 业务实验配置包、FR-25 受控双批监测业务任务和页面仍开放。真实宿主保持 `NO_GO_INDEPENDENT_EVIDENCE_INCOMPLETE`：独立来源、量表完成与 QC、首次可用时间和执行许可尚缺适用证据；监测双批也未取得合格绑定。
