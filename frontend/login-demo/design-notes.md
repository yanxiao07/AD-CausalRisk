# AD-CausalRisk 登录页 · 设计说明

## 本轮范围

- 任务：为阿尔茨海默病因果风险预测系统设计登录入口，覆盖医生、研究员、管理员、患者四种身份。
- 本轮只交付三个可运行的方向样张与对比页，不产出最终 `index.html`；方向选定后再收敛为完整登录页。
- 统一内容与状态：账号、密码（显示/隐藏）、记住我、忘记密码、四角色选择、登录失败红提示、提交 Loading。
- 设备：PC 1440×900 为主，移动端 390×844 验证。
- 示例账号仅为原型模拟：任意非空账号 + 密码 `ADrisk2026` 通过；其他密码进入失败状态。没有连接后端，也不会跳转。

## 品类与标杆

**品类**：医疗科研 SaaS 的登录入口。同品类优秀产品通常在首屏解决“这是谁的系统、我以什么权限进入、现在是否安全”三件事，信任感优先于营销感。

**拆过的真实画面**

1. `refs/ref-tdesign-login.png`（TDesign Starter 风格）
   - 左侧约 44% 是表单，右侧大块留白交给低对比 3D 抽象图形。
   - 黑色大标题、1px 细边输入框、皇家蓝实心按钮，控件克制，视觉重量集中在标题与主视觉。
   - 留用了“左操作、右叙事”的效率结构，但去掉了模板感很强的玻璃圆球，换成与疾病机制相关的因果网络。
2. `refs/ref-sketch-roles.png`（Sketch 账户类型选择）
   - 身份卡片是首屏第一主角：插画、选中描边、圆形勾选章，表单在其下。
   - 浅水蓝背景、白色卡片、圆角，但比企业后台更有照护感。
   - 留用了“先选身份、再看登录表单”的阅读顺序，扩展到四种医疗角色，并让身份联动按钮与表单标题。
3. CodePen 参考（用户提供的 URL）
   - 截图时被 Cloudflare 安全验证拦截（403），未作为视觉依据使用。见 `refs/ref-codepen.png`。

**取舍**：A 借 TDesign 的分栏与轻盈主视觉关系，转译成深色数据指挥台；B 把 Sketch 的“身份卡片先行”升级成四角色照护卡；C 主动打破“卡片式登录”的品类套路，改用暖纸、宋体与临床图谱的编辑设计。

## 三个方向

### A · 深夜证据图谱

- 北极星：让用户相信，这个系统不是简单地给出分数，而是在追踪一条可解释的风险因果链。
- 骨架：左 43.5% 表单，右 56.5% 因果网络；身份卡与表单同列，右侧身份卡随角色更新。
- 生成引擎：夜间的临床研究指挥台 + 荧光证据网络。它来自“因果推断”本身：节点、连线、路径与队列，而不是随意漂浮的 3D 球体。
- 字体：无衬线正文 + 宋体标题 + 等宽数据注释。
- 色彩：深墨海、薄荷绿、长春花蓝、冷白。薄荷色承担主动作，暗示“被验证、可继续”。
- 控件：8–10px 小圆角、1px 冷色描边、选中态用薄荷色内发光与勾选章。
- 记忆点：选中不同角色时，右侧的“当前身份”与按钮文案联动；登录失败时仅输入框转红，维持舞台的稳定感。
- 代价：信息密度最高，暗色环境在白天强光下相对吃亏。

### B · 温和照护身份卡

- 北极星：登录不是穿过一道权限门，而是找到今天自己的工作位置；适合医生与患者共用的系统。
- 骨架：居中双栏大卡片，左身份、右表单；移动端上下堆叠。
- 生成引擎：水彩医疗蓝的照护空间 + 四位角色的手绘肖像。人物和身份卡是主角，其他全部安静。
- 字体：圆润无衬线，标题短、正文易读。
- 色彩：雾蓝、湖水青、医疗蓝、暖肤色。每个角色对应一个低饱和强调色，切换身份时按钮、焦点、勾选一起换色。
- 控件：大圆角输入框、柔软投影、实心圆角按钮，触感更亲和。
- 记忆点：选中角色后，插画轻微抬起、勾选章出现，按钮上的角色称谓同步改变。
- 代价：表情最温和，科研“硬核感”依赖文案与数据安全提示来补。

### C · 临床证据手记

- 北极星：把登录页做成一份临床证据出版物的封面，冷静、可追溯，有研究机构的自信。
- 骨架：左侧 59% 是宋体标题与风险通路图，右侧 41% 是身份与登录表单；无卡片、无大圆角。
- 生成引擎：临床研究期刊/证据手记的排版语言。暖纸、网格、细线、图注和钴蓝主色来自科研出版物，而不是医疗 App 模板。
- 字体：中文宋体展示标题 + 无衬线表单 + 等宽图注/编号。
- 色彩：暖纸 `#F2EFE7`、墨色、钴蓝 `#1F3AC8`、少量赭金。钴蓝只出现在可操作和关键路径上。
- 控件：1–2px 圆角、下划线输入、方形复选框、编号式身份选项。
- 记忆点：左侧“风险证据链”图把 APOE-ε4、海马体萎缩、Tau 负荷与个体风险视图串起来；右侧身份编号与左侧图注共用一套编辑语言。
- 代价：最克制，也最依赖字体与留白；需要用户接受“论文感”而非“App 感”。

## 共同实现

- 单文件 HTML/CSS/JS，无外部图片、字体 CDN 或构建依赖；所有医疗/角色插画与数据图形均为内联 SVG/CSS。
- 三个方向各自完整的响应式布局：≥1180px 双栏，≤980px / 900px 转单栏；移动端重排而非简单缩放。
- 登录模拟：Loading 950ms；输入为空或密码不是 `ADrisk2026` 时显示红色错误；通过时显示绿色成功提示（不跳转）。
- 角色选择、密码显示/隐藏、记住我、忘记密码引导、帮助入口均可操作。
- 没有伪造用户评价、业务成功数据或产品指标；图注中的路径明确标注为“并非诊断结论”。

## 推荐

**首选 A · 深夜证据图谱。** 它最完整地同时满足“严谨、专业、现代医疗科技”：深色临床工作台带来可信的安全感，因果网络是本产品的专属视觉而不是通用 3D 装饰，角色选择还会改变当前工作台和主操作。四位角色在左栏一屏可选，比 B 更紧凑，比 C 更接近日常使用的产品登录入口。

如果这个系统未来会直接面向患者、需要明显降低紧张感，B 更合适；如果投放场景更偏学术合作、品牌想保持研究机构式的高级区分度，C 更合适。

## 已选定方向与最终实现

用户选择 **02 / 方向 B · 温和照护身份卡**。最终页面为仓库根目录的 `index.html`，保留“先选身份、再登录”的阅读顺序、四位角色的手绘肖像、医疗照护蓝与温和照护的语气。

**北极星**：登录不是穿过一道权限门，而是找到今天自己的工作位置。让医生、研究员、管理员和患者在同一入口被平等地看见，同时不牺牲医疗系统的安全与严谨。

### 最终页面要点

- 保留四张身份卡作为首屏主角；名称、职责、勾选章和轮廓共同表达选中态，不靠颜色单独表达。
- 选中描边会从旧卡滑到新卡，同时勾选章弹入、标题和 CTA 文案切换；主题色改变在 ≤100ms 内完成，避免卡片已换色而按钮仍停留在上一身份。
- 四种角色拥有独立强调色，并统一驱动选中态、焦点、按钮、帮助弹层、成功摘要与阴影。医生为医疗蓝、研究员为青绿、管理员为靛蓝、患者为陶土色。
- 展示字体改为中文 DengXian（回退 PingFang / 微软雅黑），应用于 H1、角色名、表单标题、成功标题和帮助标题；正文仍用无衬线体。DengXian 不是 web font，只在本机可用，见“限制”。
- 表单内容与标题在右栏居中到同一 400px 内容列；桌面和 768px 平板都不再左贴分隔线。
- 600px 以下身份卡改为四列紧凑卡；370px 以下压缩标题、卡片与表单纵向节奏。320×700 下主按钮完整可见，390×844 下身份、表单和主操作都在首屏。
- 角色文案全部按身份切换：患者看到“登录患者档案”“就诊卡号或手机号”和“仅展示本人的风险档案与随访信息”，不会看到工号、机构或“患者工作台”。
- 登录为前端模拟；`ADrisk2026` 为演示密码。成功使用**常驻卡片内确认视图**，替换登录表单并禁止重复提交，不再依赖会自动消失的 Toast；用户可“返回登录”继续。
- 错误提示改为密码框下方的红色 banner。真实服务不应泄露是哪一项出错，因此认证失败不再把两个字段同时标红；空值校验仍只标缺失字段。
- “记住我”默认不勾选，只保存账号，不保存密码。存储键按角色隔离：`ad-causalrisk:remembered-account:{role}`；切换身份会清空当前输入并读取目标角色自己的记忆账号。没有组织 ID，因此本轮未能加入机构维度。
- 键盘路径完整：输入框 Enter 提交，角色卡与密码显示按钮 Enter / Space 均可激活；焦点环、`aria-pressed`、`aria-invalid`、`aria-busy`、原生 `<dialog>` 焦点陷阱和成功标题焦点已处理。
- 精简了信任信息：删除顶部安全 pill、页脚实时状态与版本、表单底部的两条安全声明，仅保留身份权限说明和表单下方一条“仅限授权人员使用”。帮助弹层内保留防钓鱼与“记住我”的说明。
- 动效：首屏卡片与内容错峰入场；选中轮廓滑动；勾选章弹入；提交 Loading；错误轻抖；成功确认视图淡入。没有常驻装饰动画，`prefers-reduced-motion` 下全部立即到位。

### 登录演示

- 打开 `index.html`，选择医生 / 研究员 / 管理员 / 患者任一身份。
- 任意非空账号 + 密码 `ADrisk2026` 进入成功确认；其他密码进入失败状态。
- 成功后停留在页面内的确认视图，这是无后端原型的有意取舍；接真实鉴权时，把 `finishSuccess()` 替换为跳转即可。
